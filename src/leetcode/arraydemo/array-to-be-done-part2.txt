# 🧩 How I Recommend You Study Each Pattern

Don't simply do:

> Problem → solution → next problem.

Instead use this cycle:

```text
              ARRAY PROBLEM
                    │
                    ▼
             Identify Pattern
                    │
       ┌────────────┴────────────┐
       ▼                         ▼
   Brute Force              Optimization
       │                         │
       ▼                         ▼
   O(n²) / O(n³)          O(n) / O(n log n)
                                 │
                                 ▼
                         Explain Trade-offs
                                 │
                                 ▼
                         Code from Scratch
                                 │
                                 ▼
                       Test Edge Cases
```

For **every problem**, write down:

```text
1. Pattern:
2. Brute force:
3. Optimal approach:
4. Why it works:
5. Time complexity:
6. Space complexity:
7. Edge cases:
8. What clue tells me to use this pattern?
```

That last question is **extremely important for interviews**.

## 🔥 Most important skill for Microsoft

Don't memorize:

> "LC 560 = Prefix Sum + HashMap."

Instead train yourself to recognize:

> **"I'm looking for a contiguous subarray whose sum equals K. Repeatedly computing every subarray is expensive. Prefix sums turn this into finding whether `prefix[i] - K` existed before, so HashMap."**

That's the interview skill.

If you can look at a new problem and quickly classify it as **Two Pointer / Sliding Window / Prefix Sum / HashMap / Binary Search / Monotonic Stack / Heap / Greedy**, your preparation becomes dramatically more effective.
